# YLSpec 0.1.4

This metadata correction follows 0.1.3, which introduced improved Python package
presentation, argument checks, and context-aware VS Code completion. All of those
changes remain included. Document/frame format 0.1 and all value APIs are unchanged.

## Readable Unicode authorship

The packaging backend encoded a combined Unicode display-name/email address
using RFC 2047. PyPI displayed that encoded value literally in its Credits panel,
even though the Python overview and runtime identity showed the correct name.

Keep the creator's original spelling, **Cavanşir Qurbanzadə**, in the UTF-8
`Author` and `Maintainer` fields and store **cavanshirpro@gmail.com** separately
in the corresponding email fields with the existing **Cavanshirpro** account
handle as their ASCII contact label. YoungLionOrganization remains credited as
maintainer. No transliteration or change of copyright ownership is introduced.

Release gates now reject encoded display names in raw package headers, alongside
the existing identity, notice, URL, typing-resource, and version checks. Installed
wheel tests require a readable author field on every supported CPython version.

## Compatibility, assets, and verification

This is a distribution metadata correction. Python argument behavior and VS Code
IntelliSense are the same as 0.1.3. JavaScript, JVM, Android, and native C artifacts
receive the shared release version. Published 0.1.3 files are preserved rather
than overwritten. The [0.1.3 notes](v0.1.3.md) document the functional changes.

The complete GitHub Actions verification and fresh build run again before
publication. Assets include C libraries/headers/CLI archives, Python wheels and
source distribution, npm native/WASM package, Maven JAR/AAR distributions, and
`ylspec-0.1.4.vsix`, with `SHA256SUMS` and `build-manifest.json`.

After registry publication:

```sh
python -m pip install --upgrade ylspec==0.1.4
npm install @younglionorganization/ylspec@0.1.4
code --install-extension ylvsmp.ylspec
```
