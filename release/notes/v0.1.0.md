# YLSpec 0.1.0

The first experimental YLSpec release establishes a common metadata envelope for
standalone configuration and manifests, together with an optional binary frame
that hosts can embed in their own formats.

## Included

| Component | Behavior |
|---|---|
| Document format 0.1 | UTF-8 TOML 1.1 with `_ylspec`, `data`, and namespaced `extensions` |
| Frame 0.1 | Fixed 32-byte little-endian header and uncompressed document text |
| C11 reference core | Bounded parsing, typed values, mutation, serialization, ownership APIs |
| Embedding API | Memory decoding and offset-based callbacks without host-payload reads |
| Python package | Native CPython extension, Document, exact TemporalValue, typed errors |
| CLI | Validation, inspection, frame creation, and offset-based frame inspection |
| Profiles | Built-in `core.data` and explicit application validator registration |

## Installation and assets

Install Python distributions with `python -m pip install ylspec==0.1.0` after
publication. Native consumers can download the archive for their platform and
choose its `static/` or `shared/` installation as a CMake prefix.

| Asset family | Targets |
|---|---|
| Native C library and CLI | Linux x86_64/ARM64, Windows x64, macOS Intel/Apple Silicon |
| `abi3` Python wheels | manylinux/musllinux x86_64/ARM64, Windows AMD64, macOS x86_64/arm64 |
| Source distribution | Complete C/Python build sources and dependency notices |
| Provenance files | SHA256SUMS and build-manifest.json with source commit |

## Verification

The release workflow requires C and Python tests, platform builds, installed
wheel tests, TOML 1.1 decoder conformance, ASan/UBSan, bounded fuzzing,
documentation examples, and rendered Mermaid diagrams. Benchmark results are
workflow artifacts with environment/workload information, not universal
performance claims. Consult the release workflow run for actual results.

## Compatibility and limitations

This is an experimental 0.x API and format. No stable native ABI is promised.
The Python binding shares the C implementation and is not an independent parser.
Default limits are 16 MiB of text and depth 64, with documented parser ceilings.
Serialization does not preserve comments or whitespace and is not a signing
canonicalization format. TOML has no null value.

Frames do not authenticate metadata, compress content, locate themselves in
arbitrary files, or define the host's format. Plugin loading, package
installation, dependency resolution, mobile/WebAssembly targets, free-threaded
Python, and PyPy are outside this release.
