# YLSpec 0.1.3

This patch improves Python package identity and everyday VS Code editing while
preserving document format 0.1, frame 0.1, C ABI, and existing language APIs.

## Python package

- Provide a Python-focused PyPI overview with installation, standalone and
  embedded examples, types, limits, and complete authorship/licensing.
- Credit creator Cavanşir Qurbanzadə and maintainer YoungLionOrganization;
  preserve the public contact and add canonical documentation, source, author,
  security, issue, and release links.
- Expose typed `__author__`, `__maintainer__`, `__email__`, `__license__`,
  `__copyright__`, and `__url__` alongside `__version__`.
- Reject boolean/fractional limits and invalid frame offsets/regions before
  native conversion. Integers beyond unsigned 64-bit range cannot wrap into a
  valid frame offset; they raise `OverflowError`.
- Give `pack` the same explicit `Document` argument check as `dumps`.
- Gate release assembly on wheel/sdist metadata, Unicode attribution, SPDX
  licensing, notices, Python presentation, and installed typing resources.

## VS Code completion

| Editing action | Behavior |
|---|---|
| Enter an empty `[]` header | Standard tables and nested/namespace templates |
| Type `enabled=t` | `true` with exact replacement of the partial token |
| Enter an array value | Booleans and typed TOML value templates |
| Edit metadata | Missing keys, format/profile defaults, configured profile labels |
| Edit quoted/dotted headers | Preserve namespace boundaries and closing brackets |

Suggestions understand comments, multiline strings, inline metadata/tables,
Unicode, existing keys, and array-of-table paths. They do not infer an application
schema or register validators. `ylspec.completion.enabled`,
`ylspec.completion.autoShow`, and `ylspec.completion.profiles` control the feature.
Scanning is bounded to 1,048,576 UTF-16 code units. Formatting remains opt-in and
still removes comments and changes whitespace.

## Verification

GitHub Actions runs native C, CPython 3.11–3.15 stable ABI, wheel installs, typing,
TOML conformance, sanitizers, bounded fuzzing, documentation examples,
JavaScript/TypeScript, browser/React, JVM, Android ABI/emulator, and VS Code tests.
New regressions cover metadata completeness, offset wrapping, invalid arguments,
completion context/ranges, and accepted edits in a real VS Code Extension Host.
No unmeasured performance claims are introduced.

## Installation and assets

After each registry upload succeeds:

```sh
python -m pip install --upgrade ylspec==0.1.3
npm install @younglionorganization/ylspec@0.1.3
code --install-extension ylvsmp.ylspec
```

GitHub Release assets include C libraries/headers/CLI archives, Python wheels and
source distribution, the native/WASM npm tarball, Java/Kotlin/Maven and Android
artifacts, and `ylspec-0.1.3.vsix`. `SHA256SUMS` and `build-manifest.json` record
asset integrity and the source commit. Registry availability depends on the
corresponding publication workflow. Central requires the `xyz.younglion`
namespace to be verified before upload.

## Compatibility and limitations

Valid 0.1.2 documents and frames remain readable. JavaScript/JVM/Android artifacts
share the release version without changing value contracts. The extension remains
`ylvsmp.ylspec`. Invalid Python argument types previously accepted accidentally
now fail explicitly. Custom profiles require validators in consuming applications.
Completion is advisory; C validation is authoritative. Host formats,
authentication, and code execution remain outside the standard's scope.
